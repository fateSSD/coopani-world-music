# 一起听歌（coopani-world-music）

让桌宠陪你听歌。她知道你那边在放什么——QQ音乐或网易云音乐——**每换一首都说一句，一首歌里还要就着段落再接几句**，表情和动作跟着曲风和段落走。

- **不用告诉她**：读 Windows 的系统媒体会话（SMTC），系统级的公开接口，不注入播放器、不碰它的进程
- **不是报站机**：说什么、说多少由她判断，代码只保证在正确的时刻把事实推给她
- **看得到词**：按歌名歌手反查这一版的歌词，每段附上刚唱过的一两句，评价能落到词上（可在设置里关掉）
- **记得住**：按天的听歌记录、她标过的曲风、她记下的笔记，下次还能翻出来

## 需要什么

| 项 | 要求 |
|---|---|
| 系统 | Windows 10 / 11（读的是 Windows 的系统媒体会话） |
| 宿主 | **Coopani 0.2.16 及以上** |
| 播放器 | QQ音乐、网易云音乐，或任何向系统注册了媒体会话的播放器 |
| 形象 | 自带 `coo` / `whale` 立绘即可；换了第三方立绘包要先确认词表 |

**深听是可选能力，两条路选一条。** 基础听歌、跟拍和曲风学习都不需要它。

- **云端（默认）**：填一个 OpenAI 兼容接口的密钥就行，不装任何东西。默认地址是阿里云百炼的 `qwen-omni-turbo`，模型可以换成任何支持音频输入的模型。
- **本地**：完全在本机跑，音频不上传，但需要先装好 Python 环境和模型（约 500MB）。一条命令搞定：

  ```powershell
  powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install-hearing.ps1
  ```

  它会建一个虚拟环境、装依赖、预下载六轨分离模型和乐器分类模型，位置是
  `%LOCALAPPDATA%\CoopaniMusic\hearing`。装完回设置页把「深听方式」切成「本地」，重启一次 Core。
  要装到别处：`-Root D:\somewhere\hearing`，并把环境变量 `COOPANI_HEARING_HOME` 指到同一个目录。
  老机器上已经手工装过的（venv 和 models 分在两处）也认，不用搬。
- 两条路都只在调用 `music_listen` 时把最近 12 秒写成临时 WAV，分析完立即删除；不持续录音。

## 装

从扩展市场装上、在 World 页启用即可。本地开发用 `link:` 挂进来，步骤见文末「挂载」。

## 她会做什么

让它陪你听，而不是替你听：

| 场景 | 她的反应 |
|---|---|
| 换歌 | 一定说一句：歌名 + 歌手 + 一句态度 |
| 一首歌放到中段 | 按段评论（默认 3 段），说这一首、说你、说往后 |
| 从静默里开始听 | 开口一次，像"哟，开始了" |
| 单曲循环第 3 遍 | 提一句 |
| 连着跳歌 | 问一句是不是都不合意 |
| 深夜还在听 | 说一次，不反复念 |
| 连听很久 | 提醒一次休息 |
| 你问"在放什么" | `music_now`：歌、歌手、进度、今天第几首、这一场多久 |
| 你问"我最近听什么" | `music_history` / `music_taste`：逐日记录、常听歌手、循环曲、时段 |
| 你说"帮我暂停/下一首" | 她替你按（可在设置里关掉） |
| 一首歌放到某一段 | 附上这一段刚唱过的**一两句词**，让她的评价落在词上而不是只说音色 |
| 你问"这句唱的什么" / 聊到某句词 | `music_lyric`：现查此刻唱到哪一句，能往后多看几行 |
| 你问"这首什么乐器 / 什么调" / "你听得清吗" | `music_listen`：真去听最近十几秒（云端或本机，按设置走），回来调性、和弦、旋律、声部、乐器；多问几次会攒成整首的档案 |
| 你问"你想听什么" | `music_pick`：真去曲库里搜一首，挑中、说出理由、把链接递给你（可在设置里关掉） |
| 你想不起上次她提的那首 | `music_pick` 不带参数 = 打开想听清单，欠着哪几首一目了然 |
| 你放了她点的那首，快完了 | 剩约 35 秒时递下一首（歌名 + 链接 + 理由），最多连 6 首；你没接就不再问 |
| 你问她"你爱听什么" | 读她自己写的那份 `music-soul.md`——答的是"我吃哪一套"，不是"你常听谁" |

## 跟着真实的拍子动（0.6.0 起撤回）

> **这条路撤了。** 它靠的是往宿主 `server.ts` 加一条 `/api/audio` 路由、再放宽形象沙箱的 CSP ——
> 那是改写宿主安装目录，市集明令拉黑（cortico-extensions#659）。0.6.0 删掉整套补丁，
> 桌宠页面现在拿不到采样，动作退回**按曲库 BPM 推出来的节拍**：仍然跟歌走，但不是跟着真实鼓点。
>
> 想恢复只有一条路：向 [Pal-AI-Lab/Coopanion](https://github.com/Pal-AI-Lab/Coopanion/issues) 提需求，
> 让宿主自己开一个「把系统音频能量交给形象」的口子。扩展不再自己动宿主。

原来那套长什么样，留在这儿备查：

- 采集：`assets/audio/probe.ps1`，WASAPI 回环，把系统正在输出的声音复制一份算能量。
  **不装驱动、不带 DLL** —— 内联那段 C# 由系统自带的编译器在第一次启动时编译。
- 只算四样：BPM、响度、低音、有没有拍点。每 100ms 写进 `TEMP/coopani-audio.json`，**一个采样都不落盘**。
- ~~宿主 `server.ts` 的 `/api/audio` 把它露出来，桌宠页面每 200ms 取一次~~ ← 越界的就是这一条
- 拿不到（没开、非 Windows、刚启动还没写）就**退回原来的固定频率**，不报错也不静止。

**拍子会折八度**：140 BPM 顶一次 = 2.3Hz，是跳舞；170 BPM 就是 2.8Hz，看着像抽搐。
`beatHz()` 把频率折回 0.75–2.6Hz，太快的折半、太慢的翻倍。

**边界**：她听到的是这台机器输出的**所有**声音，包括会议和提示音。设置页可以关（`audioReactive`，默认开）。
只有 Windows 有这条通路。

## 那十二个自定义动作从哪来

蹦迪、律动、打拍子、闭眼听、跟着哼、跟拍挥、余韵、凑近听、怔住、退半步、捂耳朵听、坐着哼 ——
这些**宿主原版没有**。0.6.0 之前是本扩展往宿主包里补（改 `body.js` / `figure.json`），
那条路被市集拉黑了（改宿主安装目录，见 `cortico-extensions#659`），已经删掉。

现在改由**形象包**提供。这套扩展**自带一份**，启动时自动装到桌宠找得到的地方：

- **律动版大肥鱼** —— 底座是 Pal-AI-Lab 的 `whale`，加了这 12 个动作，随 `assets/figure-groove/` 一起发。
  首次启动拷到 `<部署>/data/figures/groove/`，按 `figure.json` 的版本号判重；换版本时先装到临时目录再整体换名，
  中途退出不会留下半个包。目录里带 `installed-by.json` 才认作自己装的 —— 你自己做了个同 id 的包，它不动。
- **装完要去换装页选它一次。** 装和用是两步，只装不选等于没装；顶部「形象包」那盏灯会说装到了哪一步。
- 想手动：把 `assets/figure-groove` 整个文件夹拷到 `data/figures/groove/`，或打包成 zip 走换装页导入。
- 原理：宿主 `act()` 碰到不认识的词会落到 `default` 分支，把 `{ kind, k }` 交给形象包自己画。
  所以**不用改宿主一行代码**。

**扩展这边不需要任何配置**：动作名按中文发（`【蹦迪】`），宿主按中文名匹配词表。
装了能用的形象包就动，没装就退回原生动作（`跳舞` / `坐下`），不会报错。

## 深听：能听出调子、和弦和乐器

能量层只给拍子和响度——知道鼓点在哪，不知道弹的是什么。想让她说得出**调性、和弦、主旋律音名、声部和乐器**，
就得"深听"：把最近十几秒切出来，送去分析。**两条路，自己选一条。**

| | 云端（默认） | 本地 |
|---|---|---|
| 要准备什么 | 一个 API 密钥（OpenAI 兼容接口） | 下载约 **500MB**（Python 环境 + 六轨分离模型 + 乐器分类模型） |
| 音频去哪 | 上传到你配的那个服务，分析完即删 | 不出这台机器，不联网 |
| 速度 | 通常几秒，取决于网络 | 本机跑，实测 12 秒切片约 **9 秒** |
| 能听出什么 | 调性、和弦、旋律音名、声部、乐器（由音频大模型判断） | 同一批字段，由本机分轨 + 信号处理算出来，乐器分类带把握度 |

**默认是云端**，因为本地那 500MB 不该让每个装扩展的人都先付一遍。装好本地环境的人可以切过去，隐私更好、也不花钱。
两条路都只分析**十几秒的切片**，不是整首总谱；`music_listen` 每调一次会把结果并进这首的档案，
所以多问几次能拼出"前面是钢琴，副歌进了鼓"这种走向——档案里会写明你听过哪几段，她不会假装听完了整首。

云端默认地址是阿里云百炼（`qwen-omni-turbo`），换成 OpenAI 兼容的其他服务只需要改「云端地址 + 模型名」两项。
没填密钥、或者选了本地但没装，她会**照实说听不了**，并在启动时提醒你一次（一天最多一次），不会装作听得见。

**攒整首**：设置里有一项「边听边攒」（`hearingEverySec`，默认 **0 = 关**）。填 60 就是每首歌每分钟偷偷听一段，
攒成这首的曲式。**云端模式下每一段都是一次计费调用**，所以默认关着，想攒的人自己开。

## 设置页

设置 → World → 一起听歌，六组：

| 组 | 里面是什么 |
|---|---|
| 她怎么开口 | 接话频率（正常 / 安静）、一首歌说几次、一段至少多长 |
| 从哪读 | 两个播放器同时开时听谁的、还认哪些播放器、多久看一次 |
| 特殊时刻 | 深夜从几点算、连续听多久算久 |
| 歌词 | 允不允许她看歌词、一次给几行（给多了她会照着念） |
| 深听方式 | 走云端还是本地（默认云端）、云端密钥/地址/模型、要不要边听边攒（默认关，云端按段计费） |
| 她自己点歌 | 允不允许她自己去搜歌挑歌、上哪个曲库找、什么时候可以挑、要不要接力点歌、允不允许她写自己的口味档案 |
| 记录与位置 | 记忆存到哪个文件夹（指向同步盘就能公司家里接同一份）、留几天、允不允许她替你按暂停 |

顶部还有两个状态灯和一个计数：`播放器` 亮不亮、`数据源` 是系统会话还是窗口标题兜底、今天听了多少首/多久。

**嫌吵**：先把「一首歌说几次」从 3 调到 2，再把「一段至少多长」从 45 调到 90；调到 0 就只剩换歌。

## 隐私与数据

- **读到什么**：当前曲目的歌名、歌手、专辑、播放位置、播放状态，以及是哪个播放器。读不到别的。
- **存哪**：默认在本机 `dataDir` 下，不上传。**记忆**（`listening/` 逐日记录、`music-notes.jsonl`、`music-tags.jsonl`、`music-wants.jsonl`、`music-soul.md`）可以在设置里改到别的文件夹——指向同步盘，公司和家里就是同一份。**当前播放状态 `music-state.json`（含接力链）和 `lyrics/` 歌词缓存永远留本机**：状态是"她以为你在听什么"，两台机器共写一份只会互相覆盖；歌词缓存随时能重取。
- **换位置不会丢旧记录**：写入走新目录，读取把本机旧目录一起读，按内容去重。切过去、切回来都不用搬文件。**口味档案是例外**：她只认新目录那一份（口味应该只有一个版本，不是两处合并），旧目录那份不动，想搬自己复制。
- **曲风学习不存音频**：`music-tags.jsonl` 里只额外保存歌名、歌手、专辑和 BPM/响度/频段能量的均值特征；不录音、不存波形。系统回环采集可在设置里关掉，关掉后元数据学习仍可用，声音近邻不再积累新样本。
- **深听：两条路，各自的隐私边界写清楚**。探针只在内存里滚动保留最近 12 秒；调用 `music_listen` 时才写一个临时 WAV，**云端模式下这十几秒会上传到你所配的服务**（否则它听不到），分析完立即删除；**本地模式下音频不出这台机器**，六轨分离和乐器分类都在本机跑。两条路的临时 WAV、请求文件、结果 JSON 都在结束时删掉，不留录音。深听档案（`music-hearing.jsonl`）只存结论——调性、和弦、音名、声部、乐器名，不存波形。
- **谁能看**：只有她和你的本地文件。她通过 `music_history` / `music_taste` 读，读的是她自己记的；口味档案是**整篇读进系统提示词**的，所以她一开口就知道自己爱听什么。
- **怎么清**：设置页这一页的「数据」页签，各项都能一键清，清完立刻生效（听歌记录 / 笔记 / 想听清单 / 曲风档案 / 口味档案 / 歌词缓存）。歌词缓存清掉不丢东西——下一段会重取；口味档案清掉只剩空骨架，文件本身留着。
- **「听歌记录保留 90 天」不会碰口味档案**：那条清理的扫描范围只有 `listening/*.jsonl`（按日期文件名匹配），口味档案在记忆目录根部、不在那个子目录里。这条有测试钉着（`test/music.test.mjs` 里的「90 天清理只删 listening/ 里的逐日记录」）。

## 已知限制

- **只能 Windows**：SMTC 是 Windows 的接口，macOS 与 Linux 装不上。
- **网易云读不到进度**：它的启动参数禁用了媒体会话上报，只能退回读窗口标题——知道在放什么，不知道放到第几秒，暂停靠 CPU 占用推断。设置页的「数据源」灯会说明当前是哪一种。
- **一首歌最多 3 段**：再密就是弹幕，她会整体被忽略。要更密自己调，但别怪她吵。
- **按播放要靠桌宠的「电脑操作」那一项**：她能搜到、挑中、把链接给你，但链接本身不会自己响——两个客户端都不接受从外部点播（网易云的 `orpheus://` 和 QQ 音乐的 `qqmusic://` 都实测过：进程能被拉起来，客户端本身不理）。想让她真的按下去，在桌宠设置里打开「电脑操作」；之后她会用鼠标点，第一次要先问你一句（宿主的规矩：别的 World 推来的消息不算授权）。
  **2026-10-29 实测**：开着电脑操作，她搜歌、双击结果、放上了，全程没让我动手；接力点歌那一条也因此能真正连下去。
- **电脑操作这条路不结实**：它靠截图认按钮，播放器换肤、缩放、弹广告都会让她点偏。所以它不是主路径——默认只递链接；她说"我放上了"之前，代码这边 `music_now` 能核对到才算数。
- **接力点歌对网易云无效**：它不上报播放进度，没有 `posSec`/`durSec` 就没有"还剩多少秒"这个判据。这条只对 QQ音乐（走 SMTC 有进度）成立。降级表现是"不触发"，日志里会说一句。
- **接力不是自动切歌**：不开电脑操作时每一棒由你按；开了她能自己按，但要先问过你。两条路都不做"偷偷替你切"。
- **词是反查来的，不是播放器给的**：系统媒体会话里没有歌词，也没有歌曲 id。她拿"歌名 + 歌手"去曲库搜一次、对上了才取词。所以冷门歌、现场版、改名上传的版本可能查不到——**查不到她会明说"这首的词我没看到"，不会自己编**。宁可这样，也不能拿错歌的词去评。
- **纯音乐会明说**：词库里标着纯音乐/无人声的，她会说"这首没词"，不会硬凑一段"唱的是思念"。
- **不读播放列表**：下一首是什么她不知道，也不猜。
- **曲风靠认，也会逐步学习**：媒体接口里没有 genre。她认得就标一次（`music_tag`）；之后同专辑、同歌手多首多数标签、以及与已标曲目接近的音频特征会给出新曲倾向，并附上依据。同歌手只有一首或证据不足时仍说"还没标"，不会硬编。
- **深听只有十几秒**：`music_listen` 听的是最近 12 秒左右的切片，不是整首总谱。调性、和弦会被转调、和声叠层和混音干扰；旋律是估算（人声轨偶尔漏进低音，已经做过八度校正，但不保证每个音）；乐器分类置信度低时她会明说"只是倾向"。"整首"是靠多听几段攒出来的档案，档案里写着听过哪几段，不会假装听完。
- **云端深听要花你的钱**：默认只在被问到时调一次；「边听边攒」默认关着，打开后每段都是一次计费调用。

## 实现说明

下面是它为什么这么做，以及踩过的坑。给要改这个扩展的人看。

### 它怎么知道你听什么

读 Windows 的系统媒体会话（SMTC）。QQ音乐和网易云音乐都会把"当前曲目/歌手/播放状态/进度"
交给系统的 `GlobalSystemMediaTransportControlsSessionManager`，这是系统级的公开接口，
不注入播放器、不读它的私有数据库、不碰它的进程。

- 常驻一个 `powershell.exe`（`scripts/nowplaying.ps1`），默认每秒输出一行 JSON；Node 侧解析，
  判变化、判水位、决定要不要推事件。
- 桥挂了会自动重连；20 秒没数据就判卡死、杀掉重来。
- 读不到时**明说读不到**（找不到 powershell / 播放器没开 / 会话不在认识的播放器里），
  不会用推测把信息补完整。

### 接力点歌的判定（为什么不会"见谁劝谁"）

`relayShouldFire()` 是纯函数（`src/relay.ts`，单测钉着），五条同时成立才推事件：

0. 这一首**被看见至少 5 秒**——刚切过来就判，会抢在「换歌了」那条前面喊"快完了"（实测 0.66 秒的错序）；
1. 现在放的**就是她递出去那首**——按歌名 + 歌手 + 时长打分，阈值 55（比查词的 65 松，因为他可能放的是现场版）；
2. 曲长 ≥ 60 秒（铃声、试听片段没有"最后一段"这个窗口）；
3. 已经播了 ≥ 20 秒（刚点开就判"快完了"是荒唐的）；
4. 剩余 ≤ 35 秒且 > 0，并且这一棒还没提醒过。

少任何一条都不开口。`firedFor` 的指纹落在 `music-state.json` 里，所以重启也不会为同一首再劝一遍；
链满 6 首、或隔半小时没用，自动作废，之后再点算新的一轮。

`count` 只数**他真放过的**那一棒（`lastPlayed`）：她挑了三次他都没点开，那就还是第一棒。
按"她说了几次"计数会假满 —— 满 6 之后再提醒就没了，而没有任何报错。

### 它会做什么

| 能力 | 说明 |
|---|---|
| 知道你听什么 | 歌名、歌手、专辑、哪个播放器、在放还是暂停、进度、这一场听了多久 |
| 每首都接话 | **每次换歌都推事件，不看歌手、没有冷却** |
| 每段都评论 | 一首歌最多说 3 段：3 分半的歌 0:45 / 1:40 / 2:35，15 分钟的古典 1:00 / 5:45 / 10:45，结尾都留白 |
| 不同的歌不同的反应 | 两个维度一起决定她的脸和语气：**路数**（烈/柔/旧/怪/淡）+ **位置**（开场/主歌/副歌/桥段/尾声一带）。摇滚的副歌给【星星眼】／【扑腾】，抒情的副歌给【喜欢】／【害羞】，老歌的副歌给【开心】／【跳舞】 |
| 在特殊时刻开口 | 从静默里开始听、单曲循环第 3 遍、连着跳歌、深夜还在听、久听 |
| 记得住 | 按天的听歌记录 + 她记的笔记，`music_history` / `music_taste` 能查 |
| 能替你按 | 暂停 / 继续 / 下一首 / 上一首（可关） |

节奏控制在**代码**里，内容不重复靠提示词：

- **段长不是固定 45 秒**：第 1 段固定 `segmentEverySec`，之后的段 `= (曲长 − 下限) / 每首段数`。
  15 分钟的古典按 45 秒切会切出 20 条——那是弹幕，只会让她被整体静音。分母不去减一，
  多出来的那一份是留给结尾的空位，否则最后一段的触发点正好落在歌曲结束那一秒，永远赶不上。
  - 4:00 的歌 → 0:45 / 2:05 / 3:10，最后 50 秒留白
  - 15:00 的古典 → 1:00 / 5:45 / 10:45，最后 4:15 留白
  - 2:00 的歌 → 0:45 / 1:30，第三段落在歌外，不触发
- 第 1 段**不参与均分**：换歌后要尽快表态。古典一个乐章十分钟，第 1 段也按均分走的话他得等四分钟才听见第一句——那不叫陪着听，叫失联。
- 抖动按「曲目 + 第几段」做确定性哈希：同一首歌来回听，段边界不漂，她的时间感才稳。
- 段计时用"这一首累计播放了多少毫秒"，不用墙钟：暂停不推进，睡醒也不会一次补发一串。
- 时间断层（≥15 分钟没在放）之后，这一首从头算、段号归零，不会拿上一场的进度接着数。
- 深夜事件一天只报一次；久听一场只报一次；重启 Core 不会重放已经报过的事件（水位落盘）。
- **分工**（写死在 `ENV_PROMPT.md` 和 `SEGMENT_ASK` 里，一条一首歌）：
  | 位置 | 说这一件事 |
  |---|---|
  | `music.track` | 《歌名》+ 歌手，紧跟着一句态度——吃不吃这一套 |
  | 第 1 段 | 只有长曲（> 6 分钟）才有：接着说，别重复开头 |
  | 第 2 段 | 说他——第几首、多久、几点、这个歌手今天第几次 |
  | 第 3 段 | 往后——下一首、还要多久，或者收尾 |

  分工是试出来的，不是设计出来的，而且改过两次。第一版让换歌"报名字"、段 1"说这个人"，结果换歌那句一定会把歌手讲完，段 1 只能复述（推理文本都一模一样）。**执行指令要写在事件正文里**，光写在提示词里不管用——她的推理原文是「The event explicitly invites a line about this segment」。
  第二版把段 1 换成"表态"，名字和态度分两条发——分工是清楚了，但用户当场发现问题：**"这一首她只说了名字和歌手没有评价啊"**。报完名字到段 1 触发中间隔着 45±15 秒，那四十多秒里她等于没反应。现在合成一条，短曲的第 1 段直接不推（`skipSignal()`），一开嗓就有内容，每首歌的说话次数不变。

### 不同歌怎么给不同反应

两个维度，来源完全不同：

**位置**由代码算。系统媒体会话给播放位置和总长，按比例切五档：
`<10%` 开场 · `<38%` 主歌 · `<70%` 副歌 · `<88%` 桥段 · 其余尾声。
**超过 6 分钟只报「开头/前段/中段/后段/收尾」，不报副歌**——古典没有副歌，按比例硬套会说出「这一首的高点」，那是编的。

**路数**从多条证据链判断（媒体接口本身没有 genre 字段），优先级从高到低：

1. **同曲标签**（`music_tag`，落盘 `music-tags.jsonl`）——认得出这首歌，比任何外推可靠，改口覆盖旧标签
2. **同专辑 / 同歌手学习**——同专辑一首即可参考；同歌手至少两首同向且占比六成以上才外推
3. **字面弱判**——只看 live / remix / 钢琴 / 古典 / 戏曲 / 老歌这类字面词，命中才算
4. **声音近邻**——至少两个同曲风样本，当前曲目的 BPM、响度和频段能量均值接近才采用，距离过远或候选拉不开差距就放弃
5. **未标**——事件里明写「路数：还没标」，绝不默认成「柔」

学习结果会带「学习依据」，不是绝对鉴定。证据不足时仍走未标闭环：邀她「认得这首就顺手 `music_tag`」，标完后面两段、以后同一首和可迁移的新歌都按更新后的档案走。

实时声音摘要也会进入换歌、段事件、`music_now` 与环境状态：她可以说感觉到拍子和低音，但只有能量与频段信息，不能据此声称听出了完整旋律或配器。

需要更细时调用 `music_listen`：本地分离六轨，分析人声旋律、调性、和弦与乐器倾向。**它只看最近约 12 秒，不是整首总谱**；乐器分类置信度低于 0.5 时只算猜测，人声轨也可能漏入伴奏造成个别八度错误。深听按需触发，不做每段自动分析。

| 路数 | 大概是什么 | 语气 | 副歌给的表情 |
|---|---|---|---|
| 烈 hard | 摇滚 / 说唱 / 电音 / 现场版 | 短、冲，句子可以不完整 | 【星星眼】/【扑腾】 |
| 柔 soft | 抒情 / 民谣 / 钢琴 / 器乐 | 轻、慢、字少 | 【喜欢】/【害羞】 |
| 旧 old | 老歌 / 戏曲 / 年代感 | 端着，带点揶揄 | 【开心】/【跳舞】 |
| 怪 odd | 实验 / 说不清路数 | 皱着眉，承认听不懂 | 【惊讶】/【星星眼】 |
| 淡 plain | 听不出什么 | 直说没感觉 | 【开心】/【喜欢】 |

完整矩阵在 `src/vibe.ts` 的 `POOL`，每格最多两个词。**两个以上她就会全写上去，气泡变成杂耍。**

表情词只从当前形象的表里取（whale：19 表情 + 22 动作；其中四个是旧版靠宿主补丁加的，0.6.0 起不再补，词表里没有就降级），**写进脚本的是中文名**（【思考】【得意】），不是英文 id。实测她看到 `【thinking】` 会推理"鲸鱼词表里没有思考"，然后换成【开心】——五档曲风全塌成一张脸。中文名和她词表里那一列一字不差，她才肯照抄。写错会被静默丢掉，所以有三条断言盯着：`POOL` 里每个词都得是词表里的中文名、`ENV_PROMPT.md` 里出现的每个 `【词】` 都必须在词表里、以及本地夹具 `test/whale-vocab.json` 与宿主 `figure.json` 对账。

### 五个动作：听歌时的身体反应

原形象只有一个跳舞动作（`dance`，原地踩着节拍摇）。后来陆续加了四个，现在一共五个，靠 `moveCue(feel, phase)` 派（`src/world.ts` 导出，纯函数，测试能单独打）：

| 动作 | 是什么 | 什么时候用 |
|---|---|---|
| 【律动】/【跟着摇】/【随拍摇】 | 只动上半身，脚不迈 | 默认。说不上路数、不想太闹 |
| 【打拍子】/【跟拍】 | 高频小幅，几乎只有一点点上下 | 老歌；烈的歌里不是高点的段落 |
| 【闭眼听】/【陶醉】 | 闭眼 + 头微抬，慢到几乎不动 | 抒情、器乐、古典的开头和收尾 |
| 【跳舞】 | 原地踩点，两只脚交替 | 轻快的歌 |
| 【蹦迪】/【蹦跶】 | 离地蹦 + 横向移动 104 px/s | 只给节奏顶上的：烈歌副歌/桥段 |

派发表：烈→副歌蹦迪、其余打拍；柔→开头收尾闭眼听、中间律动；旧→打拍；怪→副歌律动；淡→不给。**位置未知或路数未标时一律不给动作**——不知道在副歌还是在开场，猜一个就是编的。

事件正文里直接写「动作配【律动】」这种句子，不是只写在提示词里。理由同前：光写提示词她不照做。

**这几个动作宿主原本没有。** 0.6.0 起扩展不再往宿主里补 —— 词表里有就用，没有就降级到原生动作（`蹦迪` 退回 `dance`：踩拍但不横移）。

### 她不能一边放烈歌一边打盹

`body.js` 的 idle 随机池里有 `sit`（权重 16），**坐下后 60% 概率在结束前闭眼睡 8–12 秒**。实测放《曹操》，她自己坐下睡着了。

修法：`pet.lastCue` 记录"上次外面有人理她"的时刻，在 `act()` / `talk()` / `set({dialogOpen:true})` 三处刷新；`sit` 的 `willSleep` 加条件 `T - pet.lastCue > 300`。坐下可以，刚有人说话就不许当场睡；真没人管 5 分钟才打盹。

**⚠️ 改完要两步才生效**：`restart-core.ps1` 重启进程，**然后** `curl -X POST http://127.0.0.1:17788/api/session/reload-prefix`。第二步不能省——Core 重启是「恢复会话」，系统前缀（含形象词表）是缓存的，不重建。实测踩过：文件、渲染进程全确认是新的，她的推理里还是写着「"蹦迪" not in vocab」。

### 表情为什么要三重上锁

这条链踩了四轮，每轮都以为是措辞问题，其实各是一层：

1. **只给池子**（`表情走 【excited】或【flap】`）——她把"或"当建议，随手挑第三个。
2. **给中文名 + 释义**——她照样译回英文 id，然后怀疑"鲸鱼有没有这张脸"。
3. **改成硬要求**（`表情就用【X】…不按你这句话的情绪挑`）——柔/副歌照抄了【喜欢】，旧/主歌给【思考】她写"这套我吃"配【开心】：**句子往暖里走，脸就跟着暖**。
4. 真正的病根：这一节会话早先换形象时，系统发过一条"这些词用不了了 / 新增了以下"。她把那条读成"当前形象只剩 happy / love / sad / nod / shake / wave / bow / flap"，推理里留了一句 `the figure changed to whale; vocabulary lacks thinking`。之后再怎么劝都没用——**她信的是那条系统通知，不是提示词**。

修法三条一起上，缺一条都不生效：

- **语气也交给代码**（`FEEL_TONE`）：`语气：端着，带点揶揄，可以损两句`。只给脸不给语气，她会照着句子的情绪挑脸，池子等于作废。
- **第一张是定的，第二张才是"顶多换成"**：`表情就用【思考】（顶多换成【得意】）`。
- **一次性系统更正**（`vocabHint()`）：用"系统"的口吻把那条旧通知解释掉，一个数据目录只发一次（`data/vocab-hint.done`，删掉就再发）。实测发完下一段，她第一次写出了【思考】；再下一首旧歌，写的是【得意】配"稳得像端着茶杯，我吃，就是太正经了点"——路子、语气、脸终于对上了。

### 一个会掀桌的 bug：连跳歌把 Core 带走

`music.fidget`（"最近 4 分钟连跳了 5 首"）说的是人，不是某一首，所以它的 signal 里没有 `track`。而 `emit()` 开头无条件读 `signal.track.app` —— 连跳够数的那一刻就是 `TypeError`，而这句 `this.emit(...)` 没人接 rejection，Node 15 之后默认当致命错误：**一条推不出去的气泡会让整个 Core 重启**（顺带把她正在听的那首歌的段位重置）。现在两处都堵上了：`'track' in signal` 判断 + 调用点 `void this.emit(...).catch(...)`。测试 `每种事件的正文都写清了` 就是为这条加的。

### 配置

设置页「一起听歌」分六组（她怎么开口 / 从哪读 / 特殊时刻 / 歌词 / 她自己找歌 / 记录与位置），键都是 `worlds.music.*`：

| 键 | 默认 | 作用 |
|---|---|---|
| `chatiness` | `normal` | `quiet` 只报深夜/久听（**连换歌和段评论一起静音**）；`normal` 每首、每段都说 |
| `segmentEverySec` | 45 | 段长的**下限**（秒），0 = 不评论只报换歌 |
| `maxSegmentsPerTrack` | 3 | 每首最多说几段。短歌靠它压次数，长曲靠它把段长拉开 |
| `player` | `auto` | 两个播放器同时开着时听谁的（`auto`/`qq`/`netease`）|
| `extraPlayers` | 空 | 额外认作播放器的进程名片段，逗号分隔（如 `spotify`）|
| `intervalMs` | 1000 | 采样间隔。改完要重启扩展实例 |
| `nightFrom` | 23 | 深夜从几点算，窗口到清晨 5 点 |
| `longMinutes` | 100 | 连续听多久算久听 |
| `keepDays` | 90 | 听歌记录保留天数，超出的旧文件在启动时删掉 |
| `controlAllowed` | `true` | 是否允许她代你暂停/切歌 |

> `chatty` 档已经删掉：它和 `normal` 的行为完全一样，留着等于在设置页放一个不生效的选项。

**嫌吵的两个旋钮**：先调 `maxSegmentsPerTrack`（3→2，一首歌少说一次），再调 `segmentEverySec`（45→90，段长下限抬高）。调到 `segmentEverySec = 0` 就只剩换歌。

### 读不到的时候按这个顺序查

1. 播放器是不是真的在放（暂停时 SMTC 也会报会话，只是 status 是 Paused）。
2. `core.log` 里有没有「一起听歌已启动」，以及桥的 warn。
3. `/api/worlds` 看 `music` 的 lamps：`播放器` 是 `error` 就是桥挂了，`loading` 是刚起；
   `数据源` 会告诉你当前读的是系统会话还是窗口标题兜底 —— 后者本来就没有进度，别把它当故障。
4. 直接跑脚本看它输出什么：
   `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/nowplaying.ps1 -IntervalMs 1000`
5. 网易云如果一直读不到：先把 QQ音乐完全退出，确认网易云这一场确实在 SMTC 里
   （有些旧版网易云只在迷你播放器模式下注册会话）。
